## Findings ledger

**D01 — HIGH, confirmed static: ARGOS controls exposed across interfaces and origins.** [server:186–217](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L186-L217) accepts control actions including `sim.control('approve', { ticketId: body.ticketId || payload.ticketId, by: body.by || payload.by || 'dashboard-user' })`; [server:14–21](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L14-L21) returns `'access-control-allow-origin': '*'` and allows POST; [server:246–249](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L246-L249) calls `server.listen(port, '0.0.0.0', done)`. No authentication or origin check appears in that handler. Reachable peers, and browsers allowed by their network policy, can read simulation state and attempt resets, injections, approvals or benchmark runs, forging the supplied actor. This demonstrates exposure of the **simulation**, not real-world actuation. Default to loopback; enforce identity, authorization and CSRF/origin policy before any broader deployment.

**D02 — MEDIUM, confirmed static: artifact path containment is lexical.** [server:35–39](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L35-L39) checks `target.startsWith(resolve(workDir) + '/')`, while [server:141–148](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L141-L148) reads the selected file. A symlink inside the work directory could resolve outside it if an actor or another process can place one there; that precondition is not established here. Resolve real paths or use a no-follow, directory-confined open, and test traversal and symlinks. Do not claim an observed exploit.

**D03 — HIGH, confirmed static documentation: workers are not a sandbox.** [deployment:13–19](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/docs/006-deployment.md#L13-L19) states both presets run with `danger-full-access` as the operator and that wrappers `do not isolate the process`. If deployed as documented, a compromised or misdirected worker can read that account's files or execute programs, despite command shims. The guide recommends a dedicated account; verify isolation, scoped credentials, outbound access and approval gates before connecting real repositories.

**D04 — HIGH, unverified risk: model-visible source content and mutation authority share a path.** [main.ts:203–220](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/tools/main.ts#L203-L220) gives the main session tools to read candidate messages, images and files and decide assessments. [main.ts:249–263](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/tools/main.ts#L249-L263) describes settings changes as `on an explicit human configuration request, never on observed content`, then calls `host.settings.save(..., 'tool')`; [main.ts:278–296](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/tools/main.ts#L278-L296) similarly exposes prompt saving. Description text is not proof of an independent authority check. The downstream settings/prompt gates and model context framing were not inspected, so a bypass is **not confirmed**. Trace verified human provenance through those gates and test hostile issue, comment, file and tool-result instructions against changes and external effects.

**D05 — MEDIUM, owner decision / unverified risk: local management trusts local callers.** [http.ts:75–78](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/http.ts#L75-L78) requires a loopback Host, `x-orchestrator-request` and matching Origin when present; [http.ts:230–243](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/http.ts#L230-L243) enforces this after requiring a `127.0.0.1` host. This reduces ordinary cross-origin browser access, but the header is not a secret and Origin may be absent. A local process able to connect can construct the request. Decide whether same-user/local-process trust is acceptable; otherwise require authenticated, authorized management access and protect credentials.

## Five-discipline assessment

1. **Correctness/code review:** D02 is conditional on filesystem state. ARGOS's `reset` replaces the simulation while `schedule` resets `tickBusy` ([server:56–74](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L56-L74)); overlap with an already awaited tick is a concurrency risk, not a reproduced race. DSH executor's [report:85–100](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/app/tools/executor.ts#L85-L100) checks ticket liveness and atomically claims/reports/relays; retain that useful boundary.
2. **Automation/testing:** ARGOS [domains tests:84–113](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/tests/domains.test.js#L84-L113) contain approval and negative cases; they were read, not run. DSH [index test:5–12](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/tests/index.spec.ts#L5-L12) stubs Runtime, so it cannot establish real session/tool wiring. The manifest has `check`, typecheck, test and build scripts; no assertion about actual CI coverage follows from the sample.
3. **DevOps/operations:** DSH documents a database backup before upgrade and warns that a migrated DB cannot be opened by an older version ([deployment:233–242](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/docs/006-deployment.md#L233-L242)); restore has not been observed. ARGOS persists simulation events ([server:44–48](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/argos-superagent/03-app/src/web/server.js#L44-L48)); durability and concurrent recovery are unverified.
4. **OWASP/security:** D01–D05 cover authorization, prompt injection and local trust. DSH's guide says setup removes environment names containing `KEY`, `PASSWORD`, `SECRET` or `TOKEN` ([deployment:216–227](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/docs/006-deployment.md#L216-L227)); this is not proof of complete secret isolation or log redaction. Dependency integrity, CVEs, actual credential storage, retention and access to stored data remain unverified; a lockfile exists in the tree but was not inspected.
5. **UI/UX/accessibility:** DSH's [panel:124–135](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/client/app.tsx#L124-L135) labels search and icon controls; [panel:141–167](https://github.com/knarayanareddy/dshsuperagent/blob/50b188746da890569fb5770fe8d0443b5c5aaf2d/research/dsh-superagent/src/client/app.tsx#L141-L167) exposes errors and tab navigation. These are positive static indicators, not keyboard, screen-reader, contrast or responsive conformance results. ARGOS's dashboard HTML was not inspected.

## Blockers, questions and evidence limits

Before any real deployment, an owner must choose the supported product and threat model, determine who may issue approvals, provide isolated service-account credentials and a host, set retention/access controls and approve a restore/release process. Real domain claims require domain-owner validation; simulated evidence is not a substitute. DSH external provider access, account permissions, downstream policy enforcement, actual tool registration, secrets/log storage and upstream host behavior remain unverified.
