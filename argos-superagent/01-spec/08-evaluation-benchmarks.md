# 08 — Evaluation and benchmark specification

> DeepSeek's essay §7 reports p50 12.4 min vs 20.4 min and p95 15.7 vs 29.5 min for a synthetic workload, at ~2–4× cache-read tokens, and is explicit that these are preliminary, simulated results. **ARGOS-4 does not quote those as its own results.** It re-runs the *shape* of that experiment on its own event streams with its own formulas.

## 1. What is measured

| Metric | Definition | Why |
|---|---|---|
| `p50 / p95 completion` | ticks from work-request Trigger to `result.sent` | the headline latency/stability comparison |
| `routerDecisions` | number of Eval batches decided | shows the fast-path saving |
| `routerDecisionsAvoided` | Triggers delivered by subscription without Eval | essay §3.2 benefit |
| `cacheReadTokensEst` | `Σ (contextCards × tokensPerCard × sessionsAlive)` | honest cost of parallelism |
| `messagesSent`, `attentionCost` | from [`06`](06-attention-and-communication.md) | the upstream optimization target, usually missing from benchmarks |
| `speculativeWaste` | ticks of compute on discarded speculation | the cost of proactivity |
| `silenceSavings` | discards that produced zero messages | the benefit of proactivity |
| `artifactsProduced` | count of `evidence.json` files | grounding check |
| `policyViolations` | forbidden actions, word-cap breaches, worker-authored messages | must be 0 |

## 2. Two architectures on the identical event stream

**Baseline — single session with subagents (neutral prompt).** One serial ReAct loop. Every Trigger enters that loop; noise interrupts in-progress work (penalty per noise message); tasks are queued behind the current task; delegation is probabilistic and, in the neutral-prompt condition of the essay, often never happens. Follow-ups require a fresh routing decision. No speculation.

**ARGOS-4 — Router + Worker.** Code gate filters noise before any decision; explicit requests create Tickets immediately; up to `maxWorkers` tasks run concurrently; follow-ups use the fast path; speculative signals pre-start work; the Router batches queued triggers; worker completions are deterministic `effort` ticks.

Both are driven by the **same** `eventCatalog` with the same `atTick`, `effort`, and seeded evidence functions. Neither is allowed to feign work: a task completes only when its `effort` ticks have elapsed and an evidence artifact exists.

## 3. Formulas (normative, implemented in `src/metrics.js`)

```
completionTicks(task) = startTick + effortTicks + queueDelay + interruptionPenalty
queueDelay(baseline)  = Σ effort of earlier unfinished tasks
queueDelay(superagent)= waiting for a free slot (slots = maxWorkers)
interruptionPenalty(baseline) = noisePerTickWhileBusy × interruptCost
routerDecisions(superagent) = evalBatches + explicitAccepts
cacheReadTokensEst = sessionsAlive × cardsPerDecision × tokensPerCard
attentionCost = Σ receipt costs (see 06)
speculativeWaste = Σ effortTicks of discarded speculative tasks
```

No constants are tuned to force a win: `effort`, `interruptCost`, `slots` and `tokensPerCard` are declared in `benchmark.config.json` and visible in the UI.

## 4. Acceptance thresholds

| Assertion | Threshold |
|---|---|
| p95 superagent < p95 baseline | strict |
| p50 superagent < p50 baseline | strict |
| `routerDecisionsAvoided > 0` | strict |
| `cacheReadTokensEst(superagent) > cacheReadTokensEst(baseline)` | strict — the honest trade-off |
| `policyViolations == 0` | strict |
| `artifactsProduced == tasksCompleted` | strict |
| `speculativeWaste > 0` in `auto` mode | strict |
| `messagesSent / triggersIngested ≤ 0.25` | strict |
| Every percentile computed from ≥20 tasks | strict |
